## 1. Bug 修复

| 追问项 | 示例问题 |
|--------|---------|
| 实际现象 | 发生了什么？报错信息是什么？ |
| 预期现象 | 正常情况下应该怎样？ |
| 稳定复现步骤 | 怎样的操作序列能稳定触发？ |
| 报错信息或日志 | 有日志、截图或错误堆栈吗？ |
| 影响范围 | 影响哪些用户、功能或环境？ |
| 是否最近发生过相关改动 | 问题是什么时候开始的？ |
| 不能改变的现有行为 | 有哪些现有行为必须保持不变？ |
| 修复后的验收标准 | 什么结果可以确认 Bug 已修复？ |

## 2. 新功能开发

| 追问项 | 示例问题 |
|--------|---------|
| 谁使用该功能 | 目标用户是谁？ |
| 用户如何触发 | 用户通过什么入口/操作使用？ |
| 正常流程 | 正常情况下的完整流程是什么？ |
| 异常流程和边界情况 | 有哪些异常场景需要处理？ |
| 数据或状态如何变化 | 功能涉及哪些数据读写？ |
| 与现有功能的关系 | 是否依赖或影响已有功能？ |
| 是否需要兼容旧行为 | 旧版本用户会受影响吗？ |
| 该功能是否已存在 | 现有入口里有没有语义相近的功能？ |
| 完成标准 | 什么结果可以确认功能已完成？ |

## 3. 重构

| 追问项 | 示例问题 |
|--------|---------|
| 当前痛点 | 为什么要重构？当前有什么问题？ |
| 优化目标 | 重构后希望达到什么状态？ |
| 保持不变的行为 | 哪些行为必须完全不变？ |
| 是否允许调整接口/数据结构/依赖 | 重构的边界在哪里？ |
| 优先级 | 可维护性、性能、可读性哪个优先？ |
| 验证方式 | 如何确认重构没有引入回归？ |

## 4. 性能优化

| 追问项 | 示例问题 |
|--------|---------|
| 基线数据 | 当前性能指标是多少？ |
| 瓶颈证据 | 有 profiling 或监控数据吗？ |
| 目标指标 | 优化后要达到什么数字？ |
| 测量方法 | 如何测量优化效果？ |
| 可接受的 tradeoff | 愿意在哪些方面妥协？ |
| 不能影响的功能 | 哪些现有行为不能受影响？ |

## 5. UI 或交互调整

| 追问项 | 示例问题 |
|--------|---------|
| 目标页面或流程 | 涉及哪些页面或操作流程？ |
| 当前体验问题 | 当前有什么不好用的地方？ |
| 期望的视觉或交互结果 | 期望变成什么样？ |
| 响应式要求 | 需要适配哪些屏幕尺寸？ |
| 可访问性要求 | 有 WCAG 或其他无障碍要求吗？ |
| 浏览器或设备范围 | 需要支持哪些浏览器/设备？ |
| 不希望改变的页面行为 | 哪些现有交互不能动？ |

## 6. 测试补充

| 追问项 | 示例问题 |
|--------|---------|
| 测试范围 | 需要覆盖哪些模块或功能？ |
| 测试类型 | 单元测试/集成测试/E2E？ |
| 覆盖率目标 | 有覆盖率要求吗？ |
| 已有测试框架 | 项目使用什么测试框架？ |
| 边界情况要求 | 需要覆盖哪些边界情况？ |
| 验收标准 | 测试通过的标志是什么？ |

## 7. 文档改进

| 追问项 | 示例问题 |
|--------|---------|
| 目标文档 | 需要改进哪些文档？ |
| 当前问题 | 现有文档有什么不足？ |
| 目标读者 | 文档是给谁看的？ |
| 改进目标 | 希望达到什么效果？ |
| 格式要求 | 有格式或风格要求吗？ |
| 验收标准 | 什么结果可以确认文档合格？ |

## 8. 代码解释

由于本 Skill 不读取源代码：

- 帮助用户生成“交给另一个 Agent 的代码解释提示词”
- 追问：解释对象、解释深度（概览/逐行/架构级）、读者水平（新手/有经验）、输出结构（列表/表格/注释）
- 不得假装已经理解某个函数或文件的具体实现
- 如果用户直接粘贴源代码，说明本 Skill 不能分析该代码，转化为目标 Agent 的分析任务

## 10. 重新设计已有功能

**红线：未取得被重新设计对象的现状清单，不得生成最终提示词。**

完整流程、三查清单、裁决表与执行侧段落模板见 `./redesign-audit.md`。本清单只列需要问用户的问题。

### 10.1 对象与层级

| 追问项 | 示例问题 |
|--------|---------|
| 被重新设计的对象 | 要重新设计的东西叫什么？在界面的哪个位置？ |
| 变体数量 | 它有几个版本？（单选 / 多选；文件 / 文件夹；列表 / 详情） |
| 同类对照对象 | 有没有可以对照的同类对象？ |
| 本次要变的维度 | 这次要改的是功能项、分组、交互形式，还是视觉？ |

### 10.2 现状清单（必须取得）

| 追问项 | 示例问题 |
|--------|---------|
| 现有功能项清单 | 它现在有哪些功能项？能逐条列一下吗？ |
| 每项的作用对象 | 每一项作用于哪类对象？（单个 / 批量；文件 / 文件夹） |
| 每项的出现位置 | 哪一项在哪个菜单层级？有没有子菜单或面板？ |
| 清单来源可信度 | 这份清单是你确认过的，还是凭印象？ |

用户无法提供时：不要跳过。转为在提示词中注入执行侧 `<current_state_inventory>` 与 `<audit_findings_required>`（模板见 `./redesign-audit.md` 第六节），并在 `<uncertainties>` 中声明。

### 10.3 三查（导师自己判断，把结论交给用户裁决）

| 查什么 | 要问用户的问题 |
|--------|---------------|
| 对称性 | 同类对象之间，哪些项一边有一边没有？这是有意的还是历史遗留？ |
| 归属 | 某一项的作用对象和它所在的层级匹配吗？ |
| 冲突 | 你点名要的功能，和现有项有没有重复或语义重叠？ |

### 10.4 本次需求的边界

| 追问项 | 示例问题 |
|--------|---------|
| 必须保留的功能 | 现在这些功能项里，哪些必须保留、不能消失？ |
| 允许移除的功能 | 哪些可以移除？移除理由是什么？ |
| 点名的新功能 | 你要新增哪些项？ |
| 是否允许合并功能 | 有没有想把两项合成一个入口？如需合并，请单独确认 |
| 旧对象如何处置 | 重新设计后，旧的对象是替换还是并存？ |
