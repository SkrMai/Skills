# 分任务类型追问清单

根据任务类型，优先追问以下信息。只问用户能回答的、影响方案的关键问题。

追问的输出格式见 `./references/stage1-clarify.md` 第 8 节：能做成选择题的给选项，并另起一行写 **推荐：<选项>** 与一句理由（确实无倾向时写"两者皆可 —— 取决于……"），不留空。所有待确认内容集中放在回复最末。

有交互式提问工具时，能做成选择题的追问必须同时弹出可点选项（推荐项放第一个并加 `(Recommended)`，理由写进 `description`），正文选项与弹窗标签逐字一致；规则见 `SKILL.md` 第 5 节。

## 1. Bug 修复

| 追问项 | 示例问题 |
|--------|---------|
| 实际现象 | 发生了什么？报错信息是什么？ |
| 预期现象 | 正常情况下应该怎样？ |
| 稳定复现步骤 | 怎样的操作序列能稳定触发？ |
| 报错信息或日志 | 有日志、截图或错误堆栈吗？ |
| 影响范围 | 影响哪些用户、功能或环境？ |
| 是否最近发生过相关改动 | 问题是什么时候开始的？ |
| 不能改变的现有行为 | 有哪些现有行为必须保持不变？ |
| 修复后的验收标准 | 什么结果可以确认 Bug 已修复？ |

## 2. 新功能开发

| 追问项 | 示例问题 |
|--------|---------|
| 谁使用该功能 | 目标用户是谁？ |
| 用户如何触发 | 用户通过什么入口/操作使用？ |
| 正常流程 | 正常情况下的完整流程是什么？ |
| 异常流程和边界情况 | 有哪些异常场景需要处理？ |
| 数据或状态如何变化 | 功能涉及哪些数据读写？ |
| 与现有功能的关系 | 是否依赖或影响已有功能？ |
| 是否需要兼容旧行为 | 旧版本用户会受影响吗？ |
| 该功能是否已存在 | 现有入口里有没有语义相近的功能？ |
| 完成标准 | 什么结果可以确认功能已完成？ |

## 3. 重构

| 追问项 | 示例问题 |
|--------|---------|
| 当前痛点 | 为什么要重构？当前有什么问题？ |
| 优化目标 | 重构后希望达到什么状态？ |
| 保持不变的行为 | 哪些行为必须完全不变？ |

| 优先级 | 可维护性、性能、可读性哪个优先？ |
| 验证方式 | 如何确认重构没有引入回归？ |

## 8. 代码解释

| 追问项 | 示例问题 |
|--------|---------|
| 解释对象 | 要解释哪部分代码或哪个功能？ |
| 解释深度 | 概览 / 逐行 / 架构级？ |
| 读者水平 | 新手 / 有经验？ |
| 输出结构 | 列表 / 表格 / 注释？ |
| 是否需要落地 | 只要解释，还是要顺带产出改造方案？ |

本类任务通常不产生代码改动。可以自己读、或派 Subagent 读目标代码后再解释，读到的内容按证据标注（文件路径 + 行号），并区分"我读到的"与"我推断的"。不要把"读过"当成"改过"，也不要在没有证据时声称理解了某个函数的具体实现。

## 10. 重新设计已有功能

**红线：未取得被重新设计对象的现状清单（或未显式声明盲区），不得生成共识包。**

完整流程、三查清单、裁决表与执行侧兜底模板见 `./references/redesign-audit.md`；探测契约见 `./references/subagent-recon.md`。本清单只列需要问用户的问题。

### 10.1 对象与层级

| 追问项 | 示例问题 |
|--------|---------|
| 被重新设计的对象 | 要重新设计的东西叫什么？在界面的哪个位置？ |
| 变体数量 | 它有几个版本？（单选 / 多选；文件 / 文件夹；列表 / 详情） |
| 同类对照对象 | 有没有可以对照的同类对象？ |
| 本次要变的维度 | 这次要改的是功能项、分组、交互形式，还是视觉？ |

### 10.2 是否发起探测

分层判据（层一三必要条件 / 层二四维度）见 `./references/stage2-probe-audit.md` 第 2–3 节，本节不重复。本类任务几乎必然需要探测：它涉及对已有对象的重新设计，层一第 2 个必要条件不满足。探查契约见 `./references/subagent-recon.md`。

### 10.3 现状清单从哪来

优先级：**探测核实 → 用户确认 → 兜底下移执行侧**。

不要把用户当成代码事实的转述者。能自己核实的就自己核实，核实到的写进 `<verified_facts>` 并标来源；用户凭印象给出的，来源写"用户确认（凭印象）"，必要时降级进 `<unverified_assumptions>`。

| 追问项 | 示例问题 |
|--------|---------|
| 现有功能项清单 | 你印象里它现在有哪些功能项？（我会去核实） |
| 每项的作用对象 | 你期望每一项作用于哪类对象？（单个 / 批量；文件 / 文件夹） |
| 每项的出现位置 | 你知道哪一项在哪个菜单层级吗？ |
| 清单来源可信度 | 这份清单是你确认过的，还是凭印象？ |

探测与用户都拿不到时：不要跳过。转为在共识包中注入执行侧兜底要求（模板见 `./references/redesign-audit.md` 第六节），并在 `<unverified_assumptions>` 与 `<uncertainties>` 中声明。

### 10.4 三查（探测结果交用户裁决）

三查的清单与判据见 `./references/redesign-audit.md` 第四节，裁决表模板见同文件第五节。本节只列把它们转成追问时怎么问：

| 查什么 | 要问用户的问题 |
|--------|---------------|
| 对称性 | 同类对象之间，哪些项一边有一边没有？这是有意的还是历史遗留？ |
| 归属 | 某一项的作用对象和它所在的层级匹配吗？ |
| 冲突 | 你点名要的功能，和现有项有没有重复或语义重叠？ |

### 10.5 本次需求的边界

| 追问项 | 示例问题 |
|--------|---------|
| 必须保留的功能 | 现在这些功能项里，哪些必须保留、不能消失？ |
| 允许移除的功能 | 哪些可以移除？移除理由是什么？ |
| 点名的新功能 | 你要新增哪些项？ |
| 是否允许合并功能 | 有没有想把两项合成一个入口？如需合并，请单独确认 |
| 旧对象如何处置 | 重新设计后，旧的对象是替换还是并存？ |
