# 迭代模式

> 用户拿着已产出的共识包回来反馈（"效果不好""执行偏离""输出格式不对"）时读本文件。
> 本轮改动、冲突与例外用 `./templates/iteration-log.md` 记录。

---

## 1. 迭代流程

如果用户拿着之前产出的共识包回来，说"效果不好""执行偏离""输出格式不对"等，进入迭代模式：

1. **询问具体哪里不理想**：输出偏离？缺少信息？格式不符？执行时反复追问？做了一半就停？看完汇报不知道完成了什么？
2. **诊断原因**：
   - 执行时反复追问 → 共识包缺少约束或上下文
   - 执行方向错误 → 目标定义或非目标不明确
   - 输出格式不对 → 验收标准不够具体
   - 做了一半就停 → 停止条件不明确
   - 做了额外的事 → 非目标未明确或约束不够强
   - 汇报看不懂、像一堆代码关键词 → 不是共识包的问题，是执行汇报的规则；按 `./references/stage4-execute.md` 第 5 节（开头摘要、文件表写目的、遗留项分级）重发汇报，本项目无需改代码
   - 汇报像是还没做完（"要解决的""待解决"、开场写"已切换为……"）→ 同样是执行汇报的措辞问题，按 `./references/stage4-execute.md` 第 5.2 节改成完成口吻重发，本项目无需改代码
3. **输出修订版**，并明确说明：
   - 修改了什么
   - 为什么这么修改
   - 下次遇到类似情况可以怎么提前预防
4. **一致性自检（输出前必做）**：逐条核对本轮新增约束与已有约束、非目标、范围是否冲突。
   - 冲突时**必须显式写出例外条款**，并界定边界（哪部分允许动、动到什么程度不算破例）
   - 未写出例外而让两条约束互顶，视为本步骤未完成
5. **在修订说明中指出本轮新增的例外条款及其原因**，不得靠隐含消解

用 `./templates/iteration-log.md` 记录本轮改动、冲突与例外。

共识包不是一次写完的。好的共识包是迭代出来的。
